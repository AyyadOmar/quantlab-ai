# User handoff preferences

After completing work, include:

- What changed and what was checked, with material limitations.
- Whether to create a new Git branch or continue the current branch, and the recommended branch name when relevant.
- Concrete commands for reviewing, staging the relevant files, committing, and pushing to GitHub. Inspect the current Git state first when possible; do not claim a commit or push happened unless verified. Explain any blocker.
- Whether the completed work is ready to appear on the website, what should be updated, and what evidence is still needed before claiming improved model performance.

The user currently prefers public data sources. Keep historical exploratory results distinct from evidence gathered on previously untouched dates. Do not promise that a model will beat always-up or that higher accuracy implies better returns after costs.
